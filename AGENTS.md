# Prototype Instructions

- Landing 页底部三项能力说明是 Editorial / Cycling Brand 的核心理念区：三列无卡片、无横竖分割线，以留白与大标题区分；编号弱化，标题是视觉主体，不能退化成小型功能列表或 Welcome Gate 的第二套入口。
- Landing 是独立轻量首屏：实验室视觉器、Prism、Frame/Setup 面板、Modal 与 Geometry Import 必须通过动态 import 在进入实验室或上传流程后才加载；Landing DotField 初始静态绘制，交互后短暂动画，静止、后台与 reduced-motion 状态不得持续 RAF。
- Landing 底部能力区的底部 inset 与左侧 inset 使用同一响应式值，保持海报边界节奏一致。
- Landing Hero 文案与底部能力区构成同一内容栈，二者的垂直间距必须复用左侧 inset 的同一响应式 token，不使用互不关联的绝对坐标。
- Landing 右上角 `©Design By Sardine` 是低权重、可点击的开发者彩蛋入口；只在 Landing 本地打开个人故事 Modal，不新增路由、不改变 Workspace 状态。文案保持上海骑友 / UX 设计狗 / 野生开发者的个人语气，避免企业 About Us 口吻。

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

- The default `/` view is an independent `LandingPage`, while the existing laboratory remains the secondary `?view=lab` view. Landing uses exactly one full-viewport static background image: `src/assets/splash/landing-bike-parts.webp`. It must be a normal responsive image (`width: 100%; height: 100%; object-fit: cover; object-position: center`) that fills and scales with the viewport. The previous React Bits `DriftWall`, its parameter contract, its root scale, and any Accordion cover-wall visual are no longer part of the Landing production runtime. The supplied React Bits `DotField` belongs as a pointer-event-free intermediary layer above that image (`z-index: 1`) and below the full-page readability veil (`z-index: 2`) and all Landing copy (`z-index: 3+`). Keep a dark readability veil between the background and copy, plus the compact blue `进入几何实验室` CTA. Landing includes a non-interactive, low-weight three-item capability overview below the CTA: `01 快速体验` / `02 AI 几何识别` / `03 手动录入`. It is editorial information only—never cards, buttons, or alternate task entries—and the CTA remains the only route to the unchanged Welcome Gate. Landing and Workspace must share the same brand-header tokens: `--app-header-height: 64px`, `--app-shell-padding-x: 32px`, and `--app-brand-logo-height: 36px` (the shared horizontal inset reduces to 16px only below 700px). The Logo anchor must never inherit the Landing Hero's layout values. The CTA is Landing's only product entry and reveals the unchanged Welcome Gate, which exclusively owns the three first-use choices. The product Header logo may return to Landing without clearing bikes, Geometry, Fit, Components, import state, or any Workspace state; entering again restores that same in-memory state. Landing owns brand mood, Welcome Gate owns first-use choices, and Workspace owns the tool.
